# 今日工作台 · Workbench

一个高级感的个人任务看板：用「待办 / 进行中 / 已完成」三列管理当天任务，顶部以超大细体数字和环形进度呈现完成度，数据保存在本地，刷新不丢失。

- **在线体验**：https://37mba1mzk18hssq42wk.traesite.cn
- **GitHub Pages**：https://tuescool.github.io/Trae/
- **仓库地址**：https://github.com/TuesCool/Trae
- **技术形态**：单文件静态页面（HTML + CSS + 原生 JavaScript），零依赖、零构建

---

## 功能特性

| 能力 | 说明 |
| --- | --- |
| 三列看板 | 待办、进行中、已完成，列头实时显示任务数量 |
| 环形进度 | 顶部超大完成百分比 + SVG 环形进度，中心显示「已完成 / 总数」 |
| 任务管理 | 新建、编辑（标题 / 备注 / 状态）、删除，删除后支持撤销 |
| 拖拽排序 | 支持跨列拖拽改变状态、同列拖拽调整顺序，带 FLIP 位移动画 |
| 键盘操作 | 卡片可聚焦：方向键换列/排序，Enter 编辑，Delete 删除，Esc 关闭弹窗 |
| 触摸拖拽 | 触屏设备按住卡片右上角手柄拖动，即可跨列排序 |
| 本地持久化 | 使用 `localStorage` 保存，刷新、关闭后重新打开均不丢失 |
| 首次示例 | 首次打开内置 8 条可编辑的示例任务，便于直接体验 |
| 响应式 | 1080 / 880 / 520 三档断点，桌面看板与移动端单列自动切换 |
| 细节动效 | 入场错峰、数字滚动缓动、状态过渡、删除撤销 Toast |

## 操作方式

### 键盘

| 按键 | 行为 |
| --- | --- |
| `Tab` / `Shift + Tab` | 在看板卡片间移动焦点 |
| `↑` / `↓` | 在同列内上移 / 下移任务 |
| `←` / `→` | 把任务切换到上一列 / 下一列 |
| `Enter` / `Space` | 打开任务编辑弹窗 |
| `Delete` / `Backspace` | 删除任务（可通过 Toast 撤销） |
| `Esc` | 关闭编辑弹窗 |
| `Ctrl/Cmd + Enter` | 在弹窗内保存 |

焦点移动、状态切换、增删改都会通过 `aria-live` 区域播报；弹窗打开时焦点被限制在弹窗内，关闭后回到触发它的元素。

### 触摸

- 触屏设备上，卡片右上角会显示拖拽手柄，按住手柄即可拖动排序或跨列移动。
- 卡片主体仍可正常上下滚动页面；删除任务可点击卡片后在弹窗内完成。

## 界面与设计策略

**视觉语言**：雾灰到浅薄荷的柔和弥散背景，叠加极轻颗粒；半透明白色大圆角面板配合毛玻璃模糊，形成「背景 — 面板 — 卡片」三层纵深。黑色胶囊按钮承担主要动作，避免多余颜色干扰。

**色彩系统**：全页只保留一种跳色 —— 荧光黄绿 `#D8FF3E`。它被严格限制在三个语义位置：环形进度、进行中卡片整卡填充、完成勾选标记。其余信息全部交给黑、白与不同透明度的灰，保证强调色的稀缺性和辨识度。

**排版**：Inter 细体（200/300）配合 `font-variant-numeric: tabular-nums`，超大数字使用负字距收紧；中文回退到系统无衬线字体。信息层级依靠字号、字距与透明度，而不是加粗，保持轻盈。

**动效原则**：统一使用 `cubic-bezier(.22,1,.36,1)`；位移与状态过渡控制在 220–550ms，数字缓动约 700ms；拖拽重排使用 FLIP 保证元素从旧位置平滑过渡到新位置，避免布局跳变。

**交互模型**：拖拽即改变状态，降低操作成本；点击卡片打开编辑弹窗，承载标题、备注、状态与删除；删除不做二次确认，而是通过黑色 Toast + 撤销降低误操作代价。

## 技术方案与方法

### 架构

单文件架构：`index.html` 内联样式与脚本，不依赖框架、包管理器与构建流程。优势是部署成本极低（任意静态托管即可）、加载路径短、无构建产物与源码不一致的问题；代价是随功能增长需要主动拆分，已在路线图中规划。

### 数据模型

```js
{
  id: "t...",          // 唯一标识
  title: "任务标题",
  note: "备注",         // 可为空
  status: "todo",      // todo | doing | done
  order: 0,            // 列内排序
  created: 1795787967606
}
```

- 存储键：`workbench.tasks.v1`，为后续数据迁移预留版本位。
- 读取时做结构校验与容错：损坏的 JSON 或非法状态会被过滤，必要时回退到示例数据。
- 每次变更后统一 `normalize()` 重排 `order`，保证排序稳定。

### 状态与渲染

- 单一数据源 `tasks`，渲染函数按状态分组、按 `order` 排序生成卡片。
- 新增 / 编辑 / 删除走完整重渲染；拖拽过程中直接移动 DOM，拖拽结束后从 DOM 回写模型，避免高频重渲染。
- 卡片外观由所在列派生（`.col[data-status="doing"] .card`），因此跨列拖拽时无需逐个切换类名，样式随位置自然变化。
- 事件使用委托绑定在看板容器上，减少监听器数量。

### 拖拽与动效

- 基于 HTML5 Drag and Drop：`dragstart` 记录任务 ID，`dragover` 计算插入位置并实时预览，`dragend` 统一回写并更新统计。
- 重排动画采用 FLIP：先记录所有卡片位置，插入后计算位移差，通过 Web Animations API 从旧位置过渡到新位置。
- 拖拽中的卡片降低透明度并轻微缩小，作为「被拿起」的视觉反馈。

### 进度可视化

- 环形进度使用 SVG 圆环 + `stroke-dasharray / stroke-dashoffset`，通过 CSS 过渡实现平滑推进。
- 百分比数字使用 `requestAnimationFrame` + easeOutCubic 缓动，并在新动画开始前取消上一帧，避免快速操作时数字抖动。
- 无任务时环形为空，文案切换为「还没有任务」。

### 响应式

- `1080px`：进度区与统计区换行重排。
- `880px`：三列看板收为单列。
- `520px`：进度环、统计块居中堆叠，隐藏日期，保证小屏可读性。

## 本地运行

无需安装依赖与构建：

```bash
# 方式一：直接双击 index.html

# 方式二：起一个本地静态服务（推荐，便于调试 localStorage）
python -m http.server 8123
# 打开 http://127.0.0.1:8123/
```

> 数据保存在浏览器 `localStorage` 中，同一浏览器、同一访问地址（协议 + 域名 + 端口）共享数据；访问地址变化会被视为新的数据空间。

## 实现路径与优化点

### 已落地

1. **零构建单文件**：部署即发布，无工具链负担。
2. **DOM 即拖拽态**：拖拽期间只操作 DOM，结束后一次性回写模型，减少无效渲染。
3. **FLIP 重排**：跨列与同列重排都有连续位移动画，且不影响被拖拽元素。
4. **样式随列派生**：状态样式挂在列容器上，拖拽后无需重算卡片类名。
5. **撤销式删除**：Toast 内 5.2 秒撤销窗口，比确认弹窗更轻。
6. **动画可中断**：数字缓动取消旧帧，环形进度由 CSS 过渡驱动，快速连续操作不堆积。
7. **存储容错**：读取失败或数据非法时自动回退，不让页面白屏。
8. **键盘可达**：卡片可聚焦，方向键换列/排序、Enter 编辑、Delete 删除，配合焦点管理与 `aria-live` 播报。
9. **触摸拖拽**：Pointer Events + 浮动克隆层，仅在手柄上禁用滚动，兼顾移动端页面滚动与拖拽。

### 下一步优化

| 方向 | 具体优化 | 价值 |
| --- | --- | --- |
| 渲染 | 引入 keyed diff，替换整列 `innerHTML` 重建 | 保留焦点与滚动位置，减少重排 |
| 交互 | Pointer Events 自绘拖拽层，支持触摸拖拽 | 移动端可拖拽，替代仅点击改状态 |
| 可访问性 | 键盘移动任务、焦点陷阱、`aria-live` 播报 | 键盘与读屏用户可用 |
| 数据 | 导出 / 导入 JSON、存储 schema 版本迁移 | 可备份、可跨设备迁移 |
| 性能 | 长列表虚拟化、`content-visibility` | 大量任务时保持流畅 |
| 工程化 | ESM/TS 模块拆分、Vitest + Playwright | 可维护性与回归保障 |
| 交付 | GitHub Actions 自动部署 GitHub Pages | 提交即发布，版本可追溯 |

## 版本管理规范

- **版本号**：遵循 [SemVer](https://semver.org/lang/zh-CN/)：`MAJOR.MINOR.PATCH`。
- **分支**：`main` 保持可发布；功能开发使用 `feat/<name>`，修复使用 `fix/<name>`，通过合并请求进入 `main`。
- **提交信息**：遵循 Conventional Commits，例如 `feat: 增加任务导出`、`fix: 修复拖拽后计数不同步`、`docs: 更新路线图`。
- **标签**：每次发布打 `v*` 标签（如 `v1.0.0`），标签指向可运行的静态版本。
- **变更记录**：下方「版本记录」随每次发布更新；破坏性变更需在提交信息与记录中标注。

## 已知限制

- 数据仅存于当前浏览器的 `localStorage`，清空站点数据会丢失，暂不支持跨设备同步。
- 拖拽依赖 HTML5 Drag and Drop，触屏设备暂以「编辑弹窗切换状态」作为替代。
- 百分比按已完成数 / 总数四舍五入，任务量很少时可能出现显示值与直觉略有偏差。
